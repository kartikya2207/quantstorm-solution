# quantstorm-solution

My bot, and the experiment harness behind it, for **Divided Oracle**: the trading-bot game of QuantStorm 2026 (QATC IITD x FEC IITG x Quant Club IITB).

The problem statement, engine and backtester live in the organisers' repo: **[vishwasmiddha/quantstorm-ps](https://github.com/vishwasmiddha/quantstorm-ps)**. This repo only contains my own work on top of it.

## What it is

Divided Oracle is a two-player, zero-sum game. A hidden score `S` is the sum of 40 fair ±1 coins; each player holds 20 of them and sees 4 more of their own each round. Over 5 rounds the bots:

- bid in a first-price auction for one-shot "powers" (FORESIGHT, TRICK_ROOM, SUBSTITUTE, STEALTH_ROCK, TRANSFORM) out of a 24-point budget,
- take turns as Maker (opening quote, which is itself scored against `S`) and Taker,
- negotiate one contract per round over up to 6 turns, ending in an accept or a forced midpoint fill with a fee.

A submission is a single stdlib-only Python file with five methods (`reset`, `bid`, `quote`, `respond`, `use_transform`) and a 50 ms per-call limit. The entry I packaged for submission is `FINAL_SUBMISSION.py`.

## What I did

I worked on this over the competition window (most files are dated 17-18 August 2026) with an AI coding agent (Claude) doing much of the code-writing and the long test runs. My part was the steering: deciding what to test, what counted as evidence, and what was allowed to ship. `prompt.txt` is one of those instructions, kept as an example.

Roughly in order:

1. **Recon** (`recon.md`). Read the rulebook and the whole engine and wrote down how the game is *actually* scored, with line references, including places where the rulebook and the engine disagree.
2. **Baselines.** `my_bot.py` is an "insurance" entry: the organisers' `adaptive_bidder` copied verbatim, which the rulebook explicitly allows. `v2_endgame.py` added forced-fill-aware negotiation.
3. **Test opponents.** The real field was hidden, so I built opponents to test against:
   - `herd/`: 7 bots modelled on what I guessed most AI-written entries would look like,
   - `field/`: 12 more bots, each written from a different imagined "student prompt" (`f01_clone_tweak` ... `f12_tricky`), so I had something I hadn't tuned against,
   - one-off opponents such as `shift_camper.py`, `f13_defender.py`, `f14_postpatch.py`, `x1_sched12.py`, `x2_randbid.py`.
4. **Candidate bots**, one change at a time: `C1`-`C9`, `B1`-`B5`, `D1`, `E1`/`E2`, `G1`-`G3`, `H1`-`H4`, `X1`. Each file is a complete bot; the letter is the build batch.
5. **Harness.** `sweep.py` runs the official backtester over many seeds and computes paired differences on identical seeds. `gauntlet2.py`, `gauntlet_field.py`, `rr.py`, `rr5.py` and `rr_final.py` run gauntlets and round robins. `_ast_diff.py` checks that a variant differs from its parent only where intended.
6. **Selection rule.** A change was kept only if its paired 95% CI against the incumbent excluded zero *and* it wasn't meaningfully worse against any single opponent class.

The final bot (its docstring describes all six parts) combines: an exact discrete posterior over the opponent's revealed coin sum; backward-induction negotiation that prices the forced fill exactly; quote width and alignment chosen from that posterior; a within-deal opponent-archetype classifier; and a SUBSTITUTE-backed "insured" quote. `X2_sub18.py` and `X3_sub23.py` are the same bot with a different SUBSTITUTE bid, generated by `_mkvariants.py`.

## What I learnt

- **Read the engine, not just the rules.** The first big edge came from the endgame: with the engine's turn order, the Taker is always the side that pays the forced-fill fee. Making the bot aware of that was worth +48 to +119 PnL per match against the baselines in my tests (`synthesis.md`).
- **My own test herd fooled me.** `C5` (bid one tick above the predictable default bid schedule) beat `C1` by +5.19 with a "significant" CI on the herd. On the independently written field it was -0.95 and not significant (`phase4_results.md`). I had built the herd with too many bots using that exact schedule, so I was really measuring my own assumption. The conditional version (`C7`, which only snipes once the opponent's bids look like the schedule) held up on both populations.
- **Replicate before believing.** After that, anything promising had to hold on fresh seed sets and on both populations. `B4` (choosing quote width and lattice alignment from the posterior) came out at +6.23, +5.15 and +4.97 on three separate seed sets, which is what a real effect looked like (`b_build_results.md`).
- **The accept margin is there for a reason.** Three separate attempts to loosen when the bot accepts a price (`C2`, `B1`, `B3`) were each significantly worse. Accepting someone else's quoted price is adversely selected, so the fixed 0.5 margin guards against that rather than being a rounding error.
- **Ideas that didn't work:** denial bidding (pricing auctions on the opponent's value as well as mine) lost 7 to 33 PnL per match against almost everyone. Random bid jitter plus indifference mixing cost about 4.5 per match with nothing to show for it. A bid shade that rises by round (`B2`) was -1.81.
- **Real opponents are different.** Against the one real competitor entry I could test against (column `VED` in `rr_with_vedant.txt` and `rr_with_h4.txt`), every candidate lost roughly 80 to 120 per match while beating all of my synthetic bots. `H4`, a one-line change to the Taker's accept condition, brought that to +2.3. That showed me how much my synthetic opponents were missing.
- I don't have tournament results in this folder, so I'm not claiming a placing here, only what my local tests showed.

## How to run

You need Python 3.10+ and nothing else. The scripts expect the organisers' repo checked out next to this one, as a folder named `quantstorm-ps`:

```bash
mkdir quantstorm && cd quantstorm
git clone https://github.com/vishwasmiddha/quantstorm-ps.git
git clone https://github.com/kartikya2207/quantstorm-solution.git work
cd quantstorm-ps
```

Duel and validate the final bot with the official backtester:

```bash
python backtester.py --bot1 ../work/FINAL_SUBMISSION.py --bot2 strategies/adaptive_bidder.py
python backtester.py --validate ../work/FINAL_SUBMISSION.py
python backtester.py --bot1 ../work/FINAL_SUBMISSION.py --bot2 strategies/rational.py --isolate
```

Paired multi-seed comparisons, from `work/`:

```bash
cd ../work
python sweep.py --bot1 FINAL_SUBMISSION.py --bot2 field/f12_tricky.py --seeds 50
python sweep.py --compare H3_tight.py H4_takerfix.py --vs field/f06_flat8.py --seeds 60
```

`rr_final.py` and `band_probe.py` point at `vedant_v1.py` (the excluded competitor bot) by default: remove that entry from the `rr_final.py` opponent list, or pass another opponent path to `band_probe.py`. The full round robin took about 13 minutes on my machine.
